Overload without duplicating rules

Write overloaded constructors that delegate to one complete initialization path.

Complete the tasks named in your daily assignment. This page contains the full project.

Download starter + checks

Run the project

  1. Unzip into its own project folder. If you have already started this project, continue your existing working copy.
  2. Compile all Java files together. Keep any data file in the project folder.
  3. Run Card, then complete the starter tasks.
  4. Run CardCheck and explain any failing case. Do not change the check file.

Eclipse and command-line setup

Predict before running

Two constructors repeat the same validation. What bug appears when the rule changes in only one copy?

Worked example
public Card(String rank) {
  this(rank, "spades");
}

Overloading changes the parameter list, not the class name or return type. Constructor delegation must be the first statement.

Project tasks

  1. Compare paths

    Trace which fields each constructor initializes.

    Check: The incomplete path is identified.

  2. Delegate

    Use this(...) in the convenience constructor.

    Check: Default-suit check passes.

  3. Keep validation central

    Reject blank values in the complete constructor.

    Check: Both entry paths share the rule.

  4. Explain placement

    State why this(...) is first.

    Check: Java's constructor rule is named.

public class Card {
    private String rank;
    private String suit;

    public Card(String rank, String suit) {
        this.rank = rank.length() == 0 ? "?" : rank;
        this.suit = suit.length() == 0 ? "?" : suit;
    }

    public Card(String rank) {
        // TODO: delegate to the complete constructor with "spades".
        this.rank = "?";
        this.suit = "?";
    }

    public String toString() {
        return rank + " of " + suit;
    }

    public static void main(String[] args) {
        System.out.println(new Card("7", "hearts"));
        System.out.println(new Card("ace"));
    }
}
