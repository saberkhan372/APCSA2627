Design the class boundary

Separate an object's state and behavior from the code that uses it.

Complete the tasks named in your daily assignment. This page contains the full project.

Download starter + checks

Run the project

  1. Unzip into its own project folder. If you have already started this project, continue your existing working copy.
  2. Compile all Java files together. Keep any data file in the project folder.
  3. Run ClassDesign, then complete the starter tasks.
  4. Run ClassDesignCheck and explain any failing case. Do not change the check file.

Eclipse and command-line setup

Predict before running

A game has score, drawScore(), saveScore(), and readMouse(). Which two responsibilities belong inside a ScoreBoard class, and which belong to the user interface?

Worked example
class ScoreBoard {
  private int score;

  public void addPoints(int amount) {
    score += amount;
  }
}

A class boundary is a design decision. Put behavior beside the state it changes; keep screen, keyboard, and file concerns outside unless they define the object.

Project tasks

  1. Run the baseline

    Record how the starter classifies two sample responsibilities.

    Check: Both are undecided before implementation.

  2. Classify state behavior

    Return model for responsibilities that store or change the object's own data.

    Check: Field and update examples pass.

  3. Classify boundary behavior

    Return interface for drawing, keyboard, or file-delivery work.

    Check: All boundary examples pass.

  4. Write a CRC note

    Name the class, its responsibilities, and one collaborator.

    Check: The collaborator is another object, not a method.
