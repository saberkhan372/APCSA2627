Final project: feature completion

Finish required behavior and use peer tests to find edge cases.

Open slidesDaily assignmentDownload notes

Key ideas

  • Freeze optional scope until required behavior is correct.
  • A peer test should probe the public contract.
  • A reproducible bug report includes input, expected result, and actual result.

Opening prompt

A peer reports "the total is wrong". What information would make that report reproducible?

Worked example

Bug report example:
Input: prices 2.50 x 3 and 4.00 x 1
Expected total: 11.50
Actual total: 6.50
Likely question: did the calculation include quantity?

The report provides enough evidence to reproduce the behavior. The likely cause remains a hypothesis until the code or trace confirms it.

Practice

Complete required features and run peer-created boundary tests. Use the shortened 70-minute block to repair correctness issues before considering new features.

Common error

Do not add an unrelated feature to avoid investigating a known failure in the main task.

Exit check

Which peer test changed your understanding of the project’s contract?

Turn in

All required features working; bug list with reproduction steps.

After class

20 min: repair the highest-priority bug.
