Key ideas

  • The class header, fields, constructor, and methods must agree.
  • Store sufficient state without redundant values that can drift apart.
  • Match the interaction examples and the stated contract.

Worked review example

// After submission: unrelated class-design check
public class Counter {
    private int value;
    public Counter(int start) { value = start; }
    public void add(int amount) { value += amount; }
    public int getValue() { return value; }
}

The Counter example shows the relationship among stored state, initialization, mutation, and observation. It is an original review example, not a Bottle solution.

Common error

A constructor has the class name and no return type. A method that happens to share the name but has a return type is not that constructor.
