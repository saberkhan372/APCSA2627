Magic Squares lab, part 2

Validate a grid algorithm without changing the data it is inspecting.

Open slidesDaily assignmentDownload notes

Key ideas

  • Tests should isolate each required condition.
  • Keep a read-only checker free of unintended mutations.
  • A simulation update may need separate old and new grids.

Opening prompt

If you change cells while scanning their neighbors, can later cells observe a mixture of old and new values?

Worked example

Original row: 1 2 3
Rule: each new cell uses its old left neighbor.
In-place left-to-right updates can reuse changed values.
A separate next grid preserves the original observations.

The checker should only observe its input. A separate simulation example illustrates why reading one state while writing another prevents updates from contaminating later decisions.

Practice

Finish and demonstrate Magic Squares. Test a known valid square, a broken row/column/diagonal case, and the smallest supported size.

Common error

A successful check after the program silently repaired the input does not show that the original input was valid.

Exit check

How can you test whether a supposedly read-only checker changed its argument?

Turn in

Final checker, four tests and one original debugging explanation.

After class

20 min: rewrite one row/column method without compiler feedback.
