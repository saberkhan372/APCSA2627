FRQ 3: WordChecker transfer

Trace adjacent-list and String conditions without losing the contract.

Open slidesDaily assignmentDownload notes
Complete the independent attempt before using the worked review example. Your teacher supplies the selected assessment questions.

Key ideas

  • Adjacent comparisons need room for the neighbor index.
  • List order can be part of the specification.
  • A returned collection and a mutated input are different results.

Opening prompt

Before the timed attempt, identify the parameters, return types, and list side effects in WordChecker parts (a) and (b).

Worked review example

// After the attempt: original adjacent example
int equalPairs = 0;
for (int i = 0; i + 1 < words.size(); i++) {
    if (words.get(i).equals(words.get(i + 1))) {
        equalPairs++;
    }
}

The neighbor access sets the loop bound. A list with zero or one element performs zero pair comparisons. This original equal-pair example is distinct from WordChecker’s published String conditions.

Practice

Attempt both selected WordChecker parts for 30 minutes. Then trace adjacent positions, the String operation used, and any list construction or mutation.

Common error

Checking each String in isolation does not satisfy a contract about relationships between neighboring Strings.

Exit check

Why is i < words.size() insufficient when the body reads words.get(i + 1)?

Turn in

Timed list/String methods; corrected tests for adjacent entries.
