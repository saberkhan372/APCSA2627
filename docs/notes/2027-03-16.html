Unit 4 repair and consolidation

Repair a collection algorithm by tracing its first incorrect state.

Open slidesDaily assignmentDownload notes

Key ideas

  • The first incorrect state is usually more informative than the final wrong output.
  • A repair should preserve the contract on cases that already worked.
  • Recheck both boundaries and mutation behavior.

Opening prompt

A list-removal method misses the second of two adjacent matches. What state should you inspect immediately after the first removal?

Worked example

Before: [0, 0, 4]
Remove index 0: [0, 4]
Incorrect next index: 1, which skips the remaining 0
Correct forward action: recheck index 0

The first removal is correct. The next index choice creates the fault. Repairing the update can solve the problem without changing the removal condition.

Practice

Repair the two weakest collection algorithms. Explain data-file assumptions and retry a fresh search, sort, or recursion trace.

Common error

Do not rewrite an entire method before identifying the first failed assumption or state transition.

Exit check

Which previously passing case will you rerun to check that your repair did not break it?

Turn in

Corrected code; two fresh successful traces; April priority list.

After class

20 min: rehearse one ArrayList and one 2D pattern.
