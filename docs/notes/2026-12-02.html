Class design transfer and repair

Use tests to check constructor and mutator contracts.

Open slidesDaily assignmentDownload notes

Key ideas

  • An interaction table can become a sequence of executable tests.
  • Test independence by creating a second instance.
  • A method explanation should identify the fields read and the fields changed.

Opening prompt

How can two objects expose an accidental static field in a tracker class?

Worked example

StepTracker a = new StepTracker(1000);
StepTracker b = new StepTracker(1000);
a.addDailySteps(1500);
// Compare a.activeDays() with b.activeDays().

Under the original StepTracker contract, a has one active day and b has none. Their instance state must remain independent. Match all names and expected values to the supplied class specification.

Practice

Finish StepTracker, exchange boundary tests, and complete the selected Unit 3 MC questions. Explain one constructor and one mutator without the IDE.

Common error

A test that queries only the object just updated cannot expose unintended sharing across objects.

Exit check

Name the fields read and changed by addDailySteps, and explain why each belongs to the object.

Turn in

Final StepTracker; eight responses; revised class-design checklist.

After class

20 min: rehearse a fresh class specification; no additional project.
