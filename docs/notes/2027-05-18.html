Final project: design and tests

Turn the proposal into a class design and acceptance tests.

Open slidesDaily assignmentDownload notes

Key ideas

  • A design connects responsibilities with stored state and operations.
  • The data structure should match the required operations.
  • Acceptance tests describe observable behavior before implementation.

Opening prompt

What makes "it handles empty input" a more useful test when you add an exact expected result?

Worked example

Weather-tool acceptance examples:
Input 10 and 20: count 2, mean 15.0
Empty input: report "No valid readings"
Input -5 and 5: count 2, mean 0.0
Assumption: all supplied numeric tokens are valid

The examples specify behavior, including an otherwise ambiguous empty-input case. If malformed tokens are allowed, add an explicit rule and tests for them.

Practice

Specify classes, the main collection, input/output, and three acceptance tests. Build a skeleton and set two implementation milestones.

Common error

Do not write a test that simply restates the implementation instead of describing required behavior.

Exit check

Which test would fail if the most important requirement were missing?

Turn in

Design diagram, acceptance tests and runnable skeleton.

After class

20 min: implement the smallest core method.
