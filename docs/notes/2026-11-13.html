Changing People and reference ownership

Explain mutation and reassignment when a reference is passed by value.

Open slidesDaily assignmentDownload notes

Key ideas

  • A parameter receives a copy of the argument’s value.
  • An object reference can still reach shared mutable state.
  • Reassigning the parameter changes only that local reference.

Opening prompt

If a method changes a Player’s score, can the caller see the change? What if it instead reassigns the parameter?

Worked example

public static void change(Player p) {
    p.addScore(2);
    p = new Player("New", 99);
}
// Caller has Player a = new Player("Lee", 5);
// After change(a), inspect a.getScore().

The caller’s Player finishes with score 7. The new object assigned to p is separate and does not replace the caller’s reference. Java passes the reference value by value.

Practice

Trace Changing People with separate rows for the caller variable and the parameter. In the ownership project, identify any method that returns a mutable stored object directly.

Common error

Avoid the shortcut "objects are passed by reference". It obscures why parameter reassignment does not affect the caller variable.

Exit check

What is copied when an object reference is passed to a method?

Turn in

Before/after object diagrams; reference-ownership checks; a method contract.

After class

20 min: trace two aliases to one object and one reassigned parameter.
