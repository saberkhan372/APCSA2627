Final project: choose and scope

Scope a final project around one user need and one working path.

Open slidesDaily assignmentDownload notes

Key ideas

  • A useful proposal names a user and a question or task.
  • The smallest version should produce a complete result.
  • Optional features should not obscure the required behavior.

Opening prompt

Which proposal is easier to test: "make a weather app" or "summarize valid daily temperatures from a cited file"?

Worked example

Example scope:
User: a reader comparing daily temperatures
Input: a documented text file
Required result: mean of valid readings and their count
Limit: one location and one unit
Optional later: a second group comparison

This proposal reuses known parsing and aggregation skills while defining a complete minimum result. It also limits the claims the program can make about its data.

Practice

Choose a weather-data tool, Shopping Cart extension, or grid simulation. Write the user, main task, smallest working version, and what is outside the initial scope.

Common error

A list of many features is not a specification of what the first working version must do.

Exit check

Write one sentence that makes it possible to tell whether your smallest version works.

Turn in

Half-page proposal with three success criteria.

After class

20 min: refine the proposal and a sketch of the interface/model.
