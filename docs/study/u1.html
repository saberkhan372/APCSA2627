How Java runs

AP 1.1–1.3 · Draws on Quiz 1 · 13 practice questions

Key ideas

  • Compile-time errors stop a program from running at all. Run-time errors crash it while it runs. Logic errors run fine but give wrong answers.
  • Simple statements such as declarations, assignments and method calls end with a semicolon; a block in { } and a header such as if (…) do not. Strings use double quotes, and Java is case-sensitive.
  • Names use letters, digits, _ and $, cannot start with a digit, and cannot be reserved words. Classes are LikeThis; variables and methods are likeThis.
  • n bits can represent 2ⁿ different values. RAM is volatile: it loses its contents without power.

I can…

I can tell compile-time, run-time and logic errors apart.
I can spot syntax mistakes such as a missing semicolon or a bad comment.
I can tell legal names from illegal ones and follow Java's naming conventions.
I can work out how many values a number of bits can represent.
I can explain what RAM does and why it is volatile.

Expressions and types

AP 1.3–1.6 · Draws on Quiz 2 and Test 2 · 18 practice questions

Key ideas

  • int / int is an int: the fraction is truncated toward zero, not rounded. % gives the remainder, with the sign of the left operand.
  • The right side is evaluated first; assignment happens last. A double variable does not undo integer division.
  • An int can be stored in a double (widening). A double needs a cast to go into an int, and the cast truncates.
  • Where the cast goes matters: (double) a / b divides as doubles; (double) (a / b) divides as ints first.
  • An int that goes past Integer.MAX_VALUE wraps around, with no error.

I can…

I can predict int division, % and precedence, including negative numbers.
I can predict casts and say when an assignment needs one.

Output and + with Strings

AP 1.1, 1.15 · Draws on Quiz 2 and Test 2 · 13 practice questions

Key ideas

  • print leaves the cursor on the same line; println moves to the next line afterwards. Neither adds spaces.
  • \n is a new line, \t a tab, \" a quote character, and \\ a backslash.
  • + works left to right. Once one side is a String, + joins text: "a" + 1 + 2 is "a12", but 1 + 2 + "a" is "3a".
  • * / % still happen before +, so "x" + 3 * 4 is "x12".

I can…

I can predict exactly what print, println and escape sequences output.
I can predict + with Strings, working left to right.

String methods

AP 1.15 · Draws on Quiz 2b and Test 2 · 20 practice questions

Key ideas

  • Indexes start at 0 and end at length() − 1. substring(a, b) starts at a and stops before b, so its length is b − a.
  • substring(length()) and substring(k, k) are legal and return "". Going past length() throws an exception.
  • indexOf returns where the first match starts, or −1 if there is none. Case matters.
  • compareTo stops at the first different character and subtracts; if one String runs out first, it subtracts the lengths.
  • length() and indexOf return int; equals returns boolean; substring returns a String and leaves the original unchanged. No String method changes the String it is called on.

I can predict substring and length, including legal and illegal bounds.
I can use indexOf to find text and to cut a String around it.
I can compute compareTo and explain its rules.
I can use a method's header to check its arguments and return type.

Math.random and method signatures

AP 1.7–1.11 · Draws on Quiz 2b and Test 2 · 11 practice questions

Key ideas

  • Math.random() is at least 0.0 and less than 1.0. For min to max inclusive: (int) (Math.random() * (max − min + 1)) + min.
  • Cast after multiplying. (int) Math.random() is always 0.
  • A method header tells you the argument types, in order, and the return type. An int argument can go where a double is expected, but not the reverse.
  • Math.abs keeps its argument's type; Math.sqrt and Math.pow always return a double.

I can write Math.random for any inclusive range.
I can use a method's header to check its arguments and return type.

Objects and references

AP 1.12–1.14 · New for the current course (the Sep 17 AliasingLab) · 10 practice questions

Key ideas

  • new creates an object and gives back a reference to it. A variable holds the reference, not the object.
  • b = a copies the reference: both now refer to the same object, and a change through one is seen through the other.
  • Reassigning a variable points it at a different object; it does not change the old one.
  • Calling a method on null compiles but throws a NullPointerException when it runs.
  • For Strings, equals compares the characters, while == asks whether two references point to the same object. (Other classes decide for themselves what equals means.)

I can…

I can trace references, aliases, null, and == versus equals.

Initials

public static String initials(String fullName)

Returns: Returns the first letter of each name, each followed by a period: initials("Ada Lovelace") returns "A.L.".

Precondition: fullName contains exactly one space, which separates two non-empty names, with no spaces at the start or end. You do not need to handle other input.

Download starter and checker

Rubric

  1. Finds the space with indexOf instead of assuming where it is.
  2. Takes one character from the start and one just after the space, using correct substring bounds.
  3. Joins the letters and periods in the right order, and returns the result (does not print it).
  4. Keeps the method header exactly as given.

One correct solution. Yours can differ and still be right; check it against the rubric.

public static String initials(String fullName) {
    int space = fullName.indexOf(" ");
    return fullName.substring(0, 1) + "." + fullName.substring(space + 1, space + 2) + ".";
}

Percent correct

public static double percentCorrect(int correct, int total)

Returns: Returns the exact percentage of correct answers, not rounded: percentCorrect(7, 8) returns 87.5.

Precondition: total > 0 and 0 <= correct <= total. You do not need to handle other input.

Download starter and checker

Rubric

  1. Makes the division happen in double arithmetic (for example 100.0 * correct / total), so 7 of 8 gives 87.5, not 0.0 or 87.0.
  2. Does not round or cast the result to int.
  3. Returns the value (does not print it).
  4. Keeps the method header exactly as given.

One correct solution. Yours can differ and still be right; check it against the rubric.

public static double percentCorrect(int correct, int total) {
    return 100.0 * correct / total;
}
