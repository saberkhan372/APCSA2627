# FRQ 2: fresh class design

April 12, 2027 · 75 minutes

## Learning goal

Build a complete class from an interaction table.

## Key ideas

- Each required interaction imposes a behavior the class must support.

- Choose fields that can represent the state between calls.

- Match names, parameter types, and return types before implementing bodies.

## Opening prompt

Locate the required class name and the sequence of calls in the released prompt.

## Worked example — after the independent attempt

```
// After the attempt: original interaction example
Counter c = new Counter(4);
c.add(3);
int observed = c.getValue();
// Expected observed value: 7
```

The interaction implies initialization, a persistent update, and a query. A class can satisfy those behaviors with a private value field and the corresponding public methods.

## Practice

Attempt the released class task in 25 minutes. Then compare representation choices and state transitions with Bottle and StepTracker.

## Common error

Writing a method called like the class but giving it a return type does not create the required constructor.

## Exit check

Which test would reveal that a value was stored in a local variable instead of a field?

## Assignment

Attempt 2025 Q2 as a fresh class task (25 min). Compare the representation and method logic to Bottle and StepTracker; correct and explain.

## Turn in

Timed class; field/state diagram; corrected method.

## After class

20 min: one constructor/state-change trace and a short class checklist.
