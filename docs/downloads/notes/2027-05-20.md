# Final project: first working version

May 20, 2027 · 75 minutes

## Learning goal

Implement one complete path from input to result.

## Key ideas

- A working end-to-end path reveals interface mismatches early.

- Use a tiny known fixture before a large dataset.

- Keep parsing, computation, and reporting responsibilities clear.

## Opening prompt

What evidence distinguishes a working path from several methods that have never been called together?

## Worked example

```
First working path:
Read a tiny known input
Create the required objects or collection
Run the core operation
Display or return its result
Compare with one acceptance test
```

The first version can omit optional features while still completing the central task. A known fixture makes a mismatch diagnosable because the correct result is already understood.

## Practice

Implement the first complete path. Run it with a tiny fixture and explain one design decision during a code conference.

## Common error

Large realistic input can hide basic integration failures behind a plausible-looking result.

## Exit check

Which acceptance test now passes from a clean start, and what remains incomplete?

## Assignment

Implement one complete input-to-output path. Test it with a tiny fixture and explain a design decision in a code conference.

## Turn in

Runnable first version and one passing acceptance test.

## After class

25 min: finish the core feature and record the next bug.
