# Duck design and BandBooster launch

November 9, 2026 · 75 minutes

## Learning goal

Design fields and methods around an object’s responsibilities.

## Key ideas

- Instance fields represent the state each object must remember.

- Public methods describe the allowed interactions.

- A class model includes only information needed for its purpose.

## Opening prompt

A booster has a name and a sales total. Which facts vary per booster, and which actions change those facts?

## Worked example

```
public class Meter {
    private int total;
    public Meter() { total = 0; }
    public void add(int amount) { total += amount; }
    public int getTotal() { return total; }
}
```

Meter stores one fact and offers controlled ways to change and observe it. The constructor establishes the initial value. The getter returns information that any caller can use.

## Practice

Translate the Duck diagram into field and method declarations. Then sketch the BandBooster interface before implementing its bodies. Identify one unnecessary field.

## Common error

A noun in a scenario is not automatically a field. Ask whether the program must remember it between method calls.

## Exit check

Why would total normally be private while getTotal is public?

## Assignment

Turn the Duck diagram into private fields and a public interface. Design BandBooster; discuss which information the model needs and how design can exclude users.
