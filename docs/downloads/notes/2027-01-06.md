# TokenReader: text-file input

January 6, 2027 · 75 minutes

## Learning goal

Read a text file with a Scanner and a clear token contract.

## Key ideas

- File paths are interpreted relative to the program’s working directory unless absolute.

- hasNext() checks for another token before a read.

- The next method must match the token’s expected type.

## Opening prompt

What differs between a missing file and a file containing "blue" where nextInt() expects a number?

## Worked example

```
Scanner input = new Scanner(new File("values.txt"));
int total = 0;
while (input.hasNext()) {
    total += input.nextInt();
}
input.close();
```

Assume every remaining token is an integer. hasNext() establishes that a token exists, not that it has the required type. Imports and a suitable throws declaration or exception handler belong in the containing program.

## Practice

Complete TokenReader. Put the data file in the working directory, trace the tokens, and explain the imports, opening, read loop, and close call.

## Common error

Do not treat hasNext() as validation that nextInt() will succeed on arbitrary text.

## Exit check

Why can a correctly spelled data filename still fail to open during execution?
