# Portfolio handoff and course close

June 2, 2027 · 75 minutes

## Learning goal

Build a portfolio that explains growth through specific artifacts.

## Key ideas

- An artifact should support a claim about a skill.

- Before-and-after evidence makes a repaired misconception visible.

- A complete handoff includes source, run instructions, and required data.

## Opening prompt

Which is stronger evidence of learning: "I improved at arrays" or a corrected reversal trace with an explanation?

## Worked example

```
Portfolio entry example:
Claim: I can justify an in-place array update.
Evidence: original and corrected reversal traces.
Explanation: each pair swaps once using saved temporary data.
Transfer: a separate right-shift test preserves needed values.
```

The claim, artifact, explanation, and transfer case connect progress to observable work. Use the student’s chosen work through the normal classroom process, without publishing private records.

## Practice

Submit the final project and choose three artifacts covering code analysis, class design, and data processing. Explain one repaired misconception and a next learning goal.

## Common error

A portfolio of final answers alone can hide the reasoning and revisions that demonstrate learning.

## Exit check

What is one Java idea you can now explain accurately that you misunderstood earlier?

## Assignment

Submit the final project and choose three artifacts showing growth in code analysis, class design and data processing. Reflect on one repaired misconception.

## Turn in

Private portfolio/project ZIP, reflection and final test evidence.

## After class

None; follow school instructions if an additional final-exam meeting is required.
