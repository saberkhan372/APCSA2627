# StepTracker class lab

November 30, 2026 · 75 minutes

## Learning goal

Derive persistent state and boundary tests from an interaction table.

## Key ideas

- Store the information needed to answer future queries.

- Update totals and counts together when recording an observation.

- Define behavior before any observations have been recorded.

## Opening prompt

An average method has no observations yet. Why is total / count not a sufficient implementation?

## Worked example

```
int total = 1200 + 800 + 1000;
int days = 3;
double average = (double) total / days;
boolean active = 1000 >= 1000;
```

The average is 1000.0 and the threshold comparison is true. A threshold described as "at least" includes equality. Persistent tracking also needs counts that survive each recording call.

## Practice

Write StepTracker from its interaction table. Test no recorded days, one below-threshold day, one exactly-threshold day, and repeated calls.

## Common error

Do not divide total steps by active days when the method asks for the average over all recorded days.

## Exit check

What state must be updated for every recorded day, including an inactive one?
