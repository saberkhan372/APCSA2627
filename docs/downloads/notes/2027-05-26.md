# Final project: test and document

May 26, 2027 · 75 minutes

## Learning goal

Make the project reproducible for another person.

## Key ideas

- A README should explain how to start and use the program.

- Required data files and their locations are part of the handoff.

- Cite authentic data and describe limits on the result.

## Opening prompt

What might fail when a classmate starts the project from a clean folder instead of your IDE session?

## Worked example

```
README outline:
Purpose and required behavior
Required Java version and entry point
Run steps and data-file locations
One example input and expected output
Data source and known limitations
```

The README should describe the actual finished program. A clean-start test checks whether the instructions and included files are sufficient for another person to reproduce one result.

## Practice

Fix remaining bugs, run from a clean launch, and write the README, data attribution, and limitations. Rehearse a five-minute demonstration.

## Common error

Instructions that only say "press Run" do not identify the entry point, required files, or working directory.

## Exit check

Which step did a peer need clarified during the clean-start test?

## Assignment

Resolve bugs, test from a clean launch and write README instructions, data attribution and limitations. Rehearse a five-minute demo.
